# 业务规则

## 使用者

港口箱管结算员使用本工作台处理免堆日历与阶梯费率。

## 主规则

免堆期从进港次日起跳过周末和法定假日，到期后按三档日费率复算。

计算以整数最小单位或十进制定点数为准，避免二进制浮点在边界上漂移。无法完成前置校验的行进入隔离区；跨行规则在计算后标记阻断或人工复核。

## 趟次

同一箱号在本批次可以有多趟进出港，每趟是一条独立记录：

- 趟次身份为 `container_id + gate_in + gate_out`，展示编号形如 `C1@2026-11-02~2026-11-10`。
- 同箱不同进出港日期是不同趟次，各自复算费用，不再按重复冲突退还。
- 只有同箱且进出港日期完全相同、内容又不同，才按 `CONFLICT_DUPLICATE` 整趟隔离。
- 同箱多趟时，结果标签与图表条目改用趟次编号，避免箱号重名。

## 港方票据对账

票据由港方单独提供（`sample_data/tickets_*.csv`，或 API 内联提交），与箱单来源相互独立。
对账按趟核对复算费用 `fee_cents` 与票据 `amount_cents`。

配对顺序固定，不允许用金额反推归属：

1. 写明进出港日期的票据只能认领日期完全一致的趟次；日期票优先。
2. 只写箱号的旧票，仅当该箱在本批次只有一趟时才唯一配对并入账。
3. 同箱多趟时，只写箱号的旧票保持 `AMBIGUOUS` 待人工认领，即使金额与某一趟完全相同也不得认领。
4. 一张票最多入账一次，一趟最多由一张票入账；违反即 `CONFLICT` 硬阻断。
5. 同一 `ticket_id` 的多条记录按票号合并：完全重复计入重复，内容不同视为晚到修订，以最后一条为准并记 `TICKET_REVISED`。

逐趟状态：

| 状态 | 含义 | 判定影响 |
|---|---|---|
| `MATCHED` | 票据金额等于复算费用 | 不影响原判定 |
| `AMOUNT_MISMATCH` | 票据金额与复算费用不符 | 至少 `REVIEW` |
| `NO_TICKET` | 该趟没有可认领的票据 | 至少 `REVIEW` |
| `CONFLICT` | 多票认领同一趟或同票重复入账 | `REJECT`，阻断签发 |

票据侧的 `ORPHAN`（无对应趟次）、`AMBIGUOUS`（同箱多趟待认领）、`SUPERSEDED`（日期票优先）
会在对账台账里逐行列出，并让"票据全部入账或说明"检查为异常，但不单独阻断签发。

## 判定

- `PASS`：业务结果在允许范围内。
- `REVIEW`：数据可计算，但需要人工确认或存在轻微偏离。
- `REJECT`：存在来源、守恒、方向或上限阻断，不能签发。

票据对账只能收紧判定，不能把箱单侧已有的 `REVIEW`/`REJECT` 洗白。

## 批次

同一来源、同一票据归属重复执行得到同一批次数值。签发要求阻断项为零，并携带当前版本号；旧版本提交会被拒绝。证据只在签发后生成。

### 晚到票据与复核失效

- 晚到票据通过 `POST /api/runs/{id}/tickets` 并入批次；默认 `merge` 按票号覆盖同号旧记录，`replace` 表示完整重发。
- 并入后重新生成批次。若票据归属指纹（每趟认领的票号与入账金额、硬冲突集合）发生变化，
  同源旧批次标记为已失效（`invalidated`，原因 `TICKET_ATTRIBUTION_REVISED`），记录被哪个新批次替代。
- 已失效批次不能再签发、改签或下载证据，必须基于最新批次重新复核；旧复核意见不得据此签发。
- 只是新增了无对应趟次的票据、或票据行顺序变化，不改变归属指纹，旧复核保持有效。
